# 三种旅行功能的地点锁定：改动说明

## 目标

城市漫步、景点推荐和美食推荐都支持在续接计划时保留具体地点。用户可以说“保留地点2，其他重新规划”，也可以通过对应接口提交地点的 POI ID。锁定地点会随行程版本保存，后续未提及锁定状态时继续继承。

三种功能的含义有所不同：

- 城市漫步：保留地点并重新计算步行路线，不固定原来的顺序或停留时长。
- 景点推荐、美食推荐：保留备选地点，按新起点重新计算直线距离，锁定地点优先展示，其余位置重新搜索和评分。两者仍然是备选列表，不生成串联路线。

## 修改位置

1. `backend/app/models/travel.py`
   - `CityWalkPlanRequest` 增加 `locked_place_ids`。
   - 景点 `AttractionPlanRequest` 和美食 `FoodSearchRequest` 从 `DiscoveryRequest` 继承同名字段。
   - `TripState.locked_place_ids` 持久化保存 ID；默认空列表，兼容旧 JSON。
   - `TripState._previous_places` 和 `_locked_places` 仅保存本轮处理所需的旧计划信息，不写入历史 JSON。
2. `backend/app/services/preferences.py`
   - `PreferencePatch` 增加 `lock_place_names`、`unlock_place_names`、`clear_locked_places`。
   - 给提取模型提供所选旧计划中的地点 ID、名称、地址和锁定状态，支持三个功能的自然语言锁定及解锁。
3. `backend/app/agents/main_agent.py`
   - 把所选旧版本的地点提供给提取器；匹配模型提取的名称时先做完全匹配，再做唯一子串匹配。
   - 无匹配或多匹配时请求澄清；不允许将某个功能的锁定地点直接用于不同功能。
   - 自然语言锁定、解锁是增量操作。
4. `backend/app/services/trip_service.py`
   - 按所选历史版本读取完整锁定地点，并检查 ID 是否存在、重复、数量和城市。
   - 切换功能时清空当前锁定；重新编辑相应历史版本可恢复该版本的锁定。
   - 所有功能在保存前检查锁定地点确实在结果中。
5. `backend/app/agents/citywalk_agent.py`
   - 把旧计划中的锁定地点纳入候选；在对应类别的候选中显式加入未访问锁定点，将锁定信息交给 Jev 选择，仅检查当前一段路线。
   - 若目标站数等于锁定数，跳过地点搜索；无法满足锁定或顺序时不保存。
6. `backend/app/agents/discovery.py`
   - 为景点、美食提供共享的锁定地点处理：核验距当前起点的直线距离、保留原 POI、排除重复候选，并使用剩余名额评分。
   - 如果新候选均不满足偏好，允许返回锁定地点并提示数量不足。
7. `backend/app/agents/attraction_agent.py`、`backend/app/agents/food_agent.py`
   - 调用共享锁定逻辑；全部名额均已锁定时跳过搜索，搜索范围容不下锁定地点时明确报错。
8. `backend/tests/test_locked_citywalk.py`、`backend/tests/test_locked_discovery.py`
   - 覆盖三个功能的自然语言锁定、继承、解锁、歧义、无效 ID、数量和距离冲突、历史版本等情况。

## 接口契约

以下三个入口均接受 `locked_place_ids`：

- `POST /citywalk/plan`
- `POST /attraction/plan`
- `POST /food/search`

例如，续接餐厅推荐：

```json
{
  "trip_id": "trip_001",
  "state_version": 3,
  "locked_place_ids": ["A2"],
  "limit": 3
}
```

- 不传或传 `null`：继承锁定。
- 传 `[]`：解除全部锁定。
- 传非空列表：替换为这份完整的锁定列表；ID 必须属于所选计划版本。
- `base_version` 选历史版本时，以该版本的计划和锁定状态为基础；`state_version` 仍用于检查最新版本。
- 漫步请求最多锁定 5 个地点；景点和美食使用共用请求上限 1000，但实际锁定数量不能超过对应目标数量（景点 `target_stops`、美食 `limit`）。

统一自然语言入口也支持锁定和解锁。名称无法唯一匹配时返回澄清；模型输出的名称由代码核对，不直接作为 POI ID。

## 审阅注意点

- 只修改了后端，前端尚无锁定按钮。可以通过自然语言入口或上述接口使用。
- 城市漫步由 Jev 逐站选择，代码不做锁定点站位预留或未来路线枚举，并非全局最优搜索。锁定、偏好顺序和末站组合较复杂时，可能保守地报告无法满足，即使其他排列可行；搜索未命中旧锁定点时，可使用所保存或从历史恢复的真实类别来源；没有来源时不会凭空推断类别。
- 景点和美食会重新检查锁定地点是否在当前搜索半径内；超出时需要扩大范围、调整起点或解除锁定。锁定地点不重新由偏好评分筛除，餐厅口味和忌口仍需用户自行确认。
- 原地点仅固定 POI 信息；开放状态、菜单和营业时间等未重新核验。
- 自然语言识别依赖模型；名称匹配不包含别名库或语义模糊匹配。

- 全量测试执行 194 项，报告 1 项失败、14 项错误。失败项与上次检查相同：部分旧测试调用目前不存在的 `plan_legacy` / `plan_walk`，另有候选搜索测试异常。全量测试未通过。
- 测试使用离线替身，没有实际调用模型、高德或 Jev。
